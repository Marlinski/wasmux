# Third-party code, and what it means for redistribution

wasmux's own code — everything under `crates/`, `toolchain/` and `docs/` — is MIT, as
`LICENSE` says. The guest programs in `bin/` are other people's software, compiled, and they
keep their own licences. This file records which, because one of them has real obligations
attached and one combination is a genuine incompatibility.

## `bin/busybox.wasm` — GPL-2.0-only

BusyBox 1.37.0, built for `wasm32` against the musl port in `toolchain/musl`. **GPL-2.0-only**
(`only`, not `or-later`: BusyBox dropped the "or later" clause in 2006).

Distributing this binary carries the GPL's source obligation. What satisfies it is in this
repository:

- `toolchain/build-images.sh` fetches the exact upstream tarball it was built from, and the
  version is pinned in the script and recorded in `bin/MANIFEST.toml`;
- `toolchain/busybox.config` is the configuration it was built with;
- `toolchain/musl/` and `toolchain/wcc` are the complete set of local changes needed to build
  it, so the "scripts used to control compilation and installation" are here too.

If you redistribute `busybox.wasm`, keep that path intact or make an equivalent offer.

## `bin/jq.wasm` — MIT, plus BSD-2-Clause and ICU

jq 1.8.2 (MIT, © Stephen Dolan), statically linked with:

- **oniguruma** 6.9.10 — BSD-2-Clause. jq's regex engine; `test`, `match`, `sub` and friends
  do not exist without it.
- **decNumber** — ICU licence. jq's arbitrary-precision numbers.

Both come bundled in jq's own release tarball, which `toolchain/build-images.sh` fetches.

## `toolchain/musl/` — MIT

A `wasm32` port of musl 1.2.4: an architecture directory, a `crt1`, and replacements for the
handful of files that assume hardware musl cannot have here. musl is MIT, and so is this.
`toolchain/README.md` describes what each file replaces and why.

## `toolchain/csrc/sjlj-rt.c` — provenance worth checking before you rely on it

About a hundred lines implementing the runtime side of the WebAssembly `setjmp`/`longjmp`
lowering, following the reference implementation linked in its own header comment
(`llvm/llvm-project#84137`). It was carried over from a prototype and its exact upstream is
not recorded, so treat the licence as unestablished. It is small and self-contained enough to
rewrite if that matters to you.

## The compiled-in archive — a GPL/Apache incompatibility, read this

`toolchain/build-archive.sh` produces `bin/libwasmux-images.a` for the `aot` backend. That
archive is **one binary containing both**:

- C generated by `wasm2c` from `busybox.wasm`, which is a derived work of BusyBox
  (**GPL-2.0-only**); and
- wabt's `wasm-rt` runtime (`wasm-rt-impl.c` and friends), which is **Apache-2.0**.

Apache-2.0 and GPL-2.0-only are **not compatible**: Apache-2.0 adds conditions GPLv2 does not
permit, which is the FSF's own position on the pair. A combined binary of the two is therefore
not something this project can offer you a licence for.

**So the archive is not distributed here.** It is not in the repository, and this is why. Build
it yourself, for your own target, and it never leaves your build:

```sh
./toolchain/fetch-tools.sh      # wabt and a wasi-sdk
./toolchain/build-archive.sh    # -> bin/libwasmux-images.a
```

Without it, `build.rs` says so and the `interp` backend runs the same programs — slower, never
broken. See `docs/INTEGRATION.md`.

If you build an image set from sources whose licences *are* Apache-compatible, the archive is
fine to distribute and this note does not apply to it.
